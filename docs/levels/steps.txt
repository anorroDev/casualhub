КАЗУАЛ ХАБ — УРОВНИ: ПОРЯДОК РАБОТЫ ПО ШАГАМ
Ветка: levels. Полная задумка — docs/levels/design.txt. Схема — страница «Уровни Казуал Хаба».
Начато 11 ноября 2026.


================================================================================
КАК РАБОТАЕМ
================================================================================

1. Всё делается в ветке levels, на компьютере и на GitHub. В main попадает
   только законченный этап, через PR (как делает yukoma), после проверки.

2. Один шаг за раз. Следующий начинаем, только когда предыдущий доделан,
   проверен и закоммичен. Каждый шаг — отдельный коммит (или несколько), его
   можно откатить, не трогая остальное.

3. Ничего недоделанного людям не показываем. Всё про уровни спрятано за
   флагом LEVELS в wrangler.toml:
     LEVELS = "0"       — выключено, сайт как сейчас (по умолчанию)
     LEVELS = "admins"  — видно и работает только у админов
     LEVELS = "1"       — для всех
   Поэтому даже слитый в main этап ничего не меняет, пока флаг не включён.

4. Сначала невидимое, потом видимое. Сервер копит опыт, мы смотрим цифры и
   правим баланс. Интерфейс появляется только поверх уже проверенных данных.

5. Каждый шаг проверяем локально: npx wrangler pages dev . с локальной базой
   (.wrangler/state, она в .gitignore). Для проверки на настоящих данных —
   локальная копия базы из резервной копии, которая лежит на компьютере вне
   репозитория. В репозиторий и на GitHub копия базы не попадает.

6. Ветку регулярно подтягиваем к main (git rebase main), чтобы не разойтись
   с yukoma: функции API лежат в одном большом файле functions/api/[[path]].js.
   Новый код по возможности кладём в отдельные файлы (functions/_lib/levels.js),
   а в общий файл — только короткие вызовы.

7. В конце каждого этапа: «Что нового», журнал «Изменения» в админке,
   CLAUDE.md (правила для следующих правок), английские тексты в lang-en.js.


================================================================================
ЭТАП 1 — ОСНОВА
================================================================================

Шаг 1.1 — Фундамент (невидимо)
  - functions/_lib/levels.js: формула уровня, звания, таблица «за что
    сколько опыта» и лимиты — всё в одном месте.
  - Таблицы xp_log и user_level (создаются сами, как остальные таблицы сайта).
  - award(): одна функция начисления — проверки, запись в журнал, новый
    уровень. И revoke(): списание.
  - Флаг LEVELS, по умолчанию "0".
  - Тесты: формула, лимиты дня, повторное начисление, списание.
  Готово, когда: тесты проходят; с LEVELS = "0" сайт работает как раньше.

Шаг 1.2 — Начисление за действия (невидимо)
  - Вызовы award() / revoke() в оценках (PUT /shelf: сравнение «было / стало»),
    реакциях, комментариях и стене, тир-листах, друзьях, лотах, входе за день.
  - Лимиты на пару людей, проверка качества (баллы, длина текста).
  Готово, когда: локально каждое действие даёт нужный опыт, удаление
  списывает, повтор не начисляется, лимиты срабатывают.

Шаг 1.3 — Опыт за прошлое (невидимо)
  - Однократный пересчёт по уже сделанному (оценки — первые 50 по 10, дальше
    по 3; тир-листы, друзья, реакции, комментарии, лоты).
  - Запускает админ, повторный запуск ничего не удваивает.
  - Проверка на локальной копии настоящей базы: смотрим, какие уровни
    получатся у всех десятерых, и при необходимости правим баланс.
  Готово, когда: цифры на копии выглядят разумно, второй запуск ничего
  не меняет.

Шаг 1.4 — Админка «Уровни» и включение для админов
  - Вкладка в админке: опыт и уровень каждого, журнал начислений, снять опыт.
  - GET /progress (свой прогресс) — пока без интерфейса.
  - Слияние этапа-заготовки в main с LEVELS = "admins": начисление идёт по
    настоящим действиям, видят только админы, в админке.
  - 2–3 дня смотрим цифры и правим баланс.
  Готово, когда: опыт копится правильно на живом сайте, ничего не видно
  обычным людям.

Шаг 1.5 — Интерфейс уровня
  - Кольцо вокруг аватара и кружок с номером уровня в шапке.
  - Строка «Уровень 7 · Казуал · 140 / 300» в меню ☰.
  - Раздел «Прогресс» в профиле: уровень, звание, полоса, история опыта.
  - Уровень у аватара в комментариях, у друзей, в ленте и лотах.
  - Настройки → «Приватность»: «Показывать мой уровень другим».
  - Обычный и казуальный вид, телефон, английская версия.
  Готово, когда: у админов всё выглядит правильно во всех видах.

Шаг 1.6 — Достижения
  - Таблица achievements, 20–25 ачивок, проверка при каждом начислении.
  - Ачивки за прошлое и «Основатель хаба» всем нынешним.
  - Блок ачивок в «Прогрессе»: полученные, закрытые, скрытые «???», редкость.
  Готово, когда: ачивки выдаются за прошлое и за новые действия, ничего
  не выдаётся дважды.

Шаг 1.7 — Плашки наград
  - Новый уровень и новая ачивка — плашка сразу, через комнату присутствия.
  - Без сокета — в ответе /ping.
  - «+10» после сохранения оценки.
  - Настройки → «Общее»: «Уведомления о наградах».
  Готово, когда: плашка приходит на любой странице, несколько наград
  собираются в одну.

Шаг 1.8 — Выпуск этапа 1
  - «Что нового», журнал «Изменения», CLAUDE.md, README.
  - PR в main, проверка, слияние.
  - LEVELS = "1" — для всех.
