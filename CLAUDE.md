# Казуал Хаб — заметки для Claude

Этот файл Claude Code читает сам, когда открывает репозиторий. Здесь то, что нужно знать обоим разработчикам (anorro и yukomagod).

## Скилл unslop

В проекте лежит скилл **unslop** (`.claude/skills/unslop/`): он убирает «AI-вид» с интерфейса — свечения, цветные пятна, пружинные анимации, эмодзи вместо иконок, заглавные подписи с разрядкой. Автор Damir Sokolovsky ([@heydamir](https://x.com/heydamir)), оригинал: https://github.com/heydamir/unslop, лицензия CC BY 4.0 (упоминание автора оставлять).

- Claude Code подхватывает скилл из этой папки сам. Если в списке скиллов его нет, установи для своего аккаунта: скопируй папку `.claude/skills/unslop` в `~/.claude/skills/unslop` (или склонируй оригинальный репозиторий и возьми из него `skills/unslop`).
- Вызывать так: «unslop профиль», «пройдись unslop по главной».
- Стикеры roflan, реакции и конфетти на победе — часть характера сайта, это не слоп.

## Казуальный вид (unslop)

На сайте есть переключатель «Казуальный вид» (раньше назывался «Экспериментальный вид») в «Настройках», раздел «Внешний вид». Он ставит класс `unslop` на `<html>` и хранится в `localStorage` под ключом `casualhub.unslop.v1`. Обычный вид при этом не меняется.

- Класс ставят head-скрипты страниц (`hub.head.js`, `opinion/head.js`, `wheel/head.js`, `tierlist/head.js`, `profile/head.js`) до первой отрисовки. Переключатель — в `settings.js`, его обработчик — в `themes.js`.
- Тема и язык тоже меняются только в Настройках, в меню ☰ их нет. Своего меню тем у страниц нет: тему ставит `CasualThemes.apply(id, save)` из `themes.js` (`data-theme` на `<html>`, у «Авто» атрибута нет, `save` — запомнить в `ocenshik.prefs.v1`), до первой отрисовки её ставят те же head-скрипты. Текущая — `CasualThemes.current()`.
- Свои правила у каждой страницы лежат в ней самой, в `<style id="unslop-page">` перед `</head>`. Общее для всех страниц (иконки и окна из общих скриптов: подсказка, меню ☰, друзья) — в `/unslop.css`.
- Все правила казуального вида начинаются с `html.unslop` (или `:root.unslop`), чтобы не трогать обычный вид.
- Эмодзи, которые в казуальном виде становятся линейными иконками, лежат в разметке в двух вариантах: `<span class="u-old">эмодзи</span>` и `<svg class="u-new">…</svg>`. Нужный вариант показывает `/unslop.css`.
- Делаешь новую кнопку или карточку — проверь её в обоих видах.

## Сайт вживую (casualhub-rt)

- Прокрутку, вылет, победу и «до победителя» считает сервер. Общий код — `functions/_lib/lots-live.js`: его подключают и API (`functions/api`), и Worker с комнатой лотов (`rt/worker.js`). Правишь правила колеса лотов — правь там, а не в одном из них.
- Снимок `lot_rooms.live` меняется только через `liveTx` и `settledLive` (запись проходит, если снимок никто не поменял с момента чтения). После записи в D1 API зовёт `pokeRoom`, чтобы комната разослала снимок и завела будильник.
- keep/kick («Настройка лотов») уходят только админу: клиенту снимок отдаётся через `liveView`.
- Кто вылетел и какой сектор выпал — по id лота (`outIds`, `pickL`): когда ведущий разрешил повторы, два «Hades» — разные лоты. `out` и `pick` с названиями — только для показа и для старых снимков. На странице сбора сектор узнаётся так же, по `l`.
- Пульт ведущего (`lots/app.js`) шлёт в `PUT /lots/:code/live` версию `v: 2`; запрос без неё получает «обнови страницу» — так вкладки со старой страницей узнают, что сайт обновился. Меняешь, что пульт шлёт, — подними вместе `LIVE_CLIENT` в API и `LIVE_V` в `lots/app.js`.
- На странице сбора и в мини-плеере снимок приходит по сокету (`ws-client.js`), если в ответе сбора `rt: true`; без него — опрос с ETag. Новое поведение колеса проверяй в обоих режимах: с комнатой и без неё.
- Присутствие (`online.js` ↔ `PresenceDO`): общий код запросов — `functions/_lib/presence.js`, им пользуются и `POST /ping`, и комната. Поменялись друзья, заявки, «скрывать, что в сети», закрыли сеанс, пришла реакция или комментарий — API зовёт `pokePresence`. Новое событие, о котором должны узнать сразу, — добавь туда же.
- Порядок выкладки и откат — в README, раздел «Сайт вживую».

## Общие хелперы (util.js)

- `esc`, `read` и `plural` для скриптов страниц живут в `/util.js` (`window.CasualUtil`). Он подключается первым на каждой странице, раньше `/i18n.js`. Новая страница — подключи его так же; в новом скрипте бери отсюда (`const esc = window.CasualUtil.esc;`), а не объявляй заново.
- Скрипт, который нужен сразу нескольким модулям (как `/ws-client.js` для `online.js` и `lots-follow.js`), подгружай через `CasualUtil.script(src, ready)`: второй, кто попросит, дождётся того же тега.
- Офлайн-аккаунтов больше нет: без сервера регистрация и вход отказывают (friends.js). Пароль в браузере не хранится; у старых профилей до онлайн-входа — только хеш PBKDF2 (`passHash`), он стирается, когда профиль подключается к аккаунту.

## Вёрстка и скорость

- Картинки в списках и сетках (обложки, фото, лоты, гифки) — с `loading="lazy" decoding="async"`. В окнах, эффектах и бегущей строке `lazy` не ставь: там картинка нужна сразу, как только окно открылось.
- `lang-en.js` подключается из `i18n.js` через `document.write` нарочно: перевод меняет текст и подписи на холстах до первой отрисовки. С `defer` или `async` на английском мелькал бы русский.
- Новое окно или строку проверяй на ширине 320 px и на широком экране, в обоих видах. Строка настроек на узком экране сама переносит кнопку под подпись, если рядом не помещается (`settings.js`).

## Уровни и опыт

- Всё про опыт — в `functions/_lib/levels.js`: формула уровня, звания, `RULES` (за что сколько опыта и лимиты), достижения, задания, награды за уровни. API и комнаты зовут только `awardMany` / `award`, `revokeMany` / `revoke`, `visit`, `lotsWon`; сами ничего не считают. Адреса `/api/levels/*` и `/api/admin/levels*` — в `functions/_lib/levels-api.js`, на страницах — `levels-ui.js`.
- Новое действие на сайте, за которое стоит давать опыт: правило в `RULES`, вызов `lvGive(...)` в API (он сам ставит заголовок `x-levels` и шлёт сигнал другому человеку), а если действие можно удалить — `lvRevokeMany` там же, где удаление. Опыт за одно и то же дважды не дают: `ref` должен однозначно называть действие (номер оценки, комментария, «кто:на что» у реакции).
- Флаг `LEVELS` (`"0"`, `"admins"`, `"1"`) — в корневом `wrangler.toml` и в `rt/wrangler.toml` одинаковый: комната лотов по нему начисляет опыт за победу. При `"0"` таблицы уровней не создаются и ничего не пишется.
- Достижения и задания считаются по журналу `xp_log` (сколько строк каждого вида), отдельных счётчиков нет. Новое достижение — строка в `ACHIEVEMENTS`; особая мерка (`@...`) передаётся в `metrics` при начислении.
- Награды за уровни — только внешний вид. Ничего, что уже есть у всех, за уровни не закрывать.
- Тесты: `node --test tests/levels.test.mjs` (SQLite в памяти, тот же вид, что у D1).

## Резервные копии

- Каждую ночь `casualhub-rt` копирует D1 в R2: комната `BackupDO` в `rt/backup.js`, вкладка «Копии» в админке, порядок и восстановление — в README, раздел «Резервные копии».
- Новая таблица попадает в копию сама. Если в ней то, что после восстановления нарастёт заново (сеансы, лимиты, кэш), — допиши её в `SKIP` в `rt/backup.js`.
- Новый секрет в базе (хеш пароля, ключ, секрет 2FA) — допиши колонку в `SECRETS` в `rt/backup.js`: тогда в копии он зашифрован ключом `BACKUP_KEY` или пустой, а не лежит открытым текстом.
- Таблицы должны быть обычными, с rowid: по нему идут и копия, и восстановление (`rt/restore.mjs`). `WITHOUT ROWID` и виртуальные таблицы (FTS) копия не умеет.
- Из Durable Object не отвечай 503: локальная привязка принимает такой ответ за обрыв связи. Поэтому «копии выключены» комната сообщает заголовком `x-backup-off`.
